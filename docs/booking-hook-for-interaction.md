# Задание для проекта «Окно взаимодействия»: приём броней на занятия

Скопируйте этот текст целиком и передайте разработчику окна взаимодействия.

---

## Что нужно сделать

Родители записываются на занятия через форму бронирования. Как только родитель
выбрал время, наш сервис **сам** присылает вам данные о брони. Вам нужно:

1. принять этот запрос;
2. найти ученика в CRM по имени ребёнка;
3. создать (или найти) чат с этим клиентом;
4. показать в чате карточку брони — так же, как выглядит карточка сохранённого
   звонка;
5. отправить уведомление администраторам в Max/Telegram: «забронированы слоты,
   нужно завести в CRM».

Ждать и опрашивать нас не нужно — мы приходим сами, сразу после брони.

---

## 1. Точка приёма (её нужно создать у себя)

Мы шлём `POST` на ваш адрес:

```
POST https://functions.poehali.dev/67e8d62d-902a-4e5e-9862-d18395a730b1?action=booking-hook
```

Заголовки:

```
Content-Type: application/json
X-Service-Key: <INTERACTION_SERVICE_KEY>
```

`X-Service-Key` — тот же секрет, которым мы уже шлём вам список админов на
смене (`action=shift-hook`). Проверьте его так же: не совпал — верните `403`.
Сессия сотрудника здесь не нужна: запрос идёт от сервиса, а не от человека.
**Сейчас на этот адрес приходит `401 no_session` — значит, обработчик ещё не
написан.**

### Тело запроса

```json
{
  "event": "booking_created",
  "batchId": "-cQO1BH0Np0",
  "child": {
    "name": "Иванова Маша",
    "parentName": "",
    "phone": ""
  },
  "startFrom": "2026-09-01",
  "createdAt": "2026-08-28T13:48:10.540030+00:00",
  "lessons": [
    {
      "id": 31,
      "lessonType": "individual",
      "weekday": "Понедельник",
      "date": "2026-09-07",
      "timeFrom": "15:00",
      "timeTo": "15:40",
      "teacherId": 18,
      "teacherName": "Анна Карамова"
    },
    {
      "id": 32,
      "lessonType": "groups",
      "weekday": "Суббота",
      "date": "2026-09-05",
      "timeFrom": "11:00",
      "timeTo": "11:40",
      "teacherId": 17,
      "teacherName": "Екатерина К."
    }
  ]
}
```

### Пояснения к полям

| Поле | Смысл |
|---|---|
| `event` | Всегда `booking_created`. На будущее — могут появиться другие события. |
| `batchId` | Номер заявки. Все занятия одной отправки имеют общий `batchId` — это **одна заявка**, а не несколько. |
| `child.name` | Фамилия и имя ребёнка, как ввёл родитель. Может быть с опечаткой, в любом порядке слов. |
| `child.phone` | Часто **пустой**. По общей ссылке телефон не спрашивается. |
| `child.parentName` | Часто пустой — заполнен только для персональных ссылок. |
| `startFrom` | Дата, с которой родитель готов начать занятия. |
| `lessons[]` | Все выбранные занятия. Может быть 1, может быть 5. |
| `lessons[].lessonType` | `individual` — индивидуальное, `groups` — групповое. |
| `lessons[].weekday` | День недели. **Занятия регулярные**: «Понедельник 15:00» — это каждый понедельник, а не одна дата. |
| `lessons[].date` | Дата первого занятия. Нужна для справки, ориентируйтесь на день недели. |
| `lessons[].timeFrom/timeTo` | Время занятия, 40 минут. |
| `lessons[].teacherName` | Педагог. |

### Ответ, который мы ждём

```json
{ "ok": true, "dialogId": 42 }
```

Любой ответ со статусом `200` считаем успехом. Ошибку тоже вернуть можно —
бронь у нас сохранится в любом случае, просто в логах будет отметка.
Отвечайте **быстро** (до 3 секунд): тяжёлую работу — поиск в CRM, отправку
уведомлений — выносите в фон, иначе наш запрос отвалится по таймауту.

## 2. Что сделать с полученной бронью

### 2.1. Найти ученика в CRM

Телефона чаще всего нет, поэтому ищите **по имени ребёнка**. Имя приходит
как написал родитель, поэтому сравнивать «в лоб» нельзя. Учтите:

- порядок слов любой: «Маша Иванова» = «Иванова Маша»;
- отчество может быть, а может не быть: «Иванова Мария Сергеевна»;
- уменьшительные имена: Маша = Мария, Поля = Полина, Настя = Анастасия,
  Саша = Александр/Александра, Соня = София, Лиза = Елизавета;
- «ё» и «е», разный регистр, лишние пробелы, дефисы;
- опечатка в одну букву: «Борычива» = «Борычева», «Мирия» = «Мария»;
- род фамилии: «Иванов» и «Иванова» — одна семья.

**Важно, чего делать нельзя:** склеивать разных детей. «Маша Иванова» и
«Даша Иванова» — сёстры, это разные ученики. Если фамилия указана только у
одного из имён, связывать по одному имени рискованно — лучше не связывать.

У нас эта логика уже написана и работает, можете взять её за образец:
`backend/slot-bookings/name_match.py` — там разбор имени на фамилию/имя,
словарь уменьшительных форм и сравнение с допуском на одну опечатку. Рядом
лежит `test_name_match.py` с 17 проверками, включая пары, которые склеивать
нельзя.

### 2.2. Создать или найти чат

- Если телефон пришёл — ищите диалог по нему (`chat_id` или `phone`).
- Если телефона нет — ищите по имени ребёнка среди диалогов.
- Не нашли — заводите новый диалог: канал `max`, статус «Лид»,
  `child_name` = имя из заявки. Чтобы `chat_id` не конфликтовал, используйте
  что-то вроде `booking-<id первого занятия>`.
- Нашли — не создавайте дубль, просто допишите сообщение в существующий чат.

### 2.3. Показать карточку брони в чате

Оформите так же, как карточку сохранённого звонка — отдельным блоком, не
обычным текстовым сообщением. Что должно быть видно:

- заголовок: «Заявка на занятия» (или «на занятие», если оно одно);
- имя ребёнка;
- дата начала занятий;
- список всех занятий: день недели, время, педагог, тип (группа /
  индивидуально);
- пометка, что ученика **нужно завести в CRM** — это главное действие
  администратора.

Диалог поднимите наверх списка и увеличьте счётчик непрочитанных: заявка не
должна потеряться.

### 2.4. Отправить уведомление админам

В Max или Telegram — куда у вас настроено. Текст примерно такой:

```
Новая бронь: Иванова Маша
Начало с 01.09.2026

• Понедельник 15:00–15:40 — Анна Карамова (индивидуально)
• Суббота 11:00–11:40 — Екатерина К. (группа)

Нужно добавить ученика в CRM.
```

Кому слать: администраторам, которые сейчас на смене. Их список вы уже
получаете от нас через `action=shift-hook`.

## 3. Откуда забрать брони, если запрос потерялся

Мы шлём запрос один раз. Если ваш сервис в этот момент лежал, заявку можно
забрать самим — есть открытый адрес со списком:

```
GET https://functions.poehali.dev/1f1f495f-752e-4470-b50c-51490b382f89?action=feed&status=new
```

`status`: `new` — необработанные, `all` — все, `confirmed`, `rejected`.

Ответ:

```json
{
  "bookings": [
    {
      "id": 31,
      "batchId": "-cQO1BH0Np0",
      "childName": "Иванова Маша",
      "parentName": "",
      "phone": "",
      "startFrom": "2026-09-01",
      "status": "new",
      "statusLabel": "Новая",
      "dialogId": null,
      "createdAt": "2026-08-28T13:48:10+00:00",
      "lessons": [
        {
          "id": 31,
          "lessonType": "individual",
          "weekdayName": "Понедельник",
          "date": "2026-09-07",
          "timeFrom": "15:00",
          "timeTo": "15:40",
          "teacherId": 18,
          "teacherName": "Анна Карамова"
        }
      ]
    }
  ],
  "newCount": 1
}
```

Заявки уже сгруппированы: один элемент `bookings` = одна заявка, внутри
`lessons` — все её занятия. `newCount` считает заявки, а не занятия.

Разумный запасной вариант — опрашивать этот адрес раз в 2–3 минуты и
досылать то, что не пришло по хуку. Ориентир для сверки — `batchId`.

## Короткий чек-лист

- [ ] Создан обработчик `action=booking-hook`, проверяет `X-Service-Key`,
      сессию сотрудника не требует.
- [ ] Отвечает за 3 секунды, тяжёлое — в фон.
- [ ] Ученик ищется в CRM по имени с учётом уменьшительных форм и опечаток.
- [ ] Разные дети одной семьи не склеиваются.
- [ ] Чат находится или создаётся, дубли не плодятся.
- [ ] В чате появляется карточка брони со всеми занятиями и пометкой
      «завести в CRM».
- [ ] Уведомление уходит админам на смене в Max/Telegram.
- [ ] Есть подстраховка: периодический опрос `action=feed&status=new`.
