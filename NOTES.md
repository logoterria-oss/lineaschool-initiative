# Заметки по проекту

## Отложено: Единое окно коммуникации с клиентами

Вернуться к этой задаче позже. Договорённости с заказчиком:

**Цель:** собрать всё общение с клиентами (Max, Telegram, звонки) в единую ленту
«Коммуникация» у каждого ученика, с удобной передачей между сотрудниками
(диагност / админ / руководитель).

**Вводные от заказчика:**
- Max подключён через Wappi, всё на одном номере телефона.
- Телефония: пока НЕ звоним по API, записей звонков нет (расшифровка — только когда
  появится IP-телефония с записью; Yandex SpeechKit уже доступен в проекте).
- Единую ленту хранить у нас, в разделе «Коммуникация»; в AlfaCRM (S20) — только
  короткие пометки (у S20 нет API-метода писать переписку в карточку).
- Вход сотрудников: личный вход у каждого. ЛОГИН = НОМЕР ТЕЛЕФОНА.
- Регистрация: САМОСТОЯТЕЛЬНАЯ (сотрудник регистрируется сам → руководитель
  подтверждает/активирует аккаунт). До подтверждения — доступа нет.
- Охват: ВСЕ сотрудники, ВКЛЮЧАЯ ПЕДАГОГОВ. Роли: педагог, диагност, администратор,
  руководитель. Масштаб 15–40 человек, состав меняется → таблица сотрудников в БД
  + раздел управления, ручной хардкод-список ADMINS больше НЕ подходит.
- Первый приоритет заказчика: **передача общения между сотрудниками**.

**РЕШЕНО начать с ЭТАПА 0 (личные кабинеты сотрудников) ДО окна коммуникации.**
- Переход: старый общий пароль 426874 РАБОТАЕТ ПАРАЛЛЕЛЬНО с новым личным входом
  (пока все не зарегистрируются). НЕ отключаем сразу.
- Роль при регистрации: сотрудник ВЫБИРАЕТ САМ → руководитель подтверждает/меняет.

**Текущее состояние кода (важно для старта):**
- Есть основа «Взаимодействия»: таблицы `student_interactions`,
  `student_interaction_replies`, `student_comments`. UI —
  `src/components/students/InteractionsCell.tsx`, `CommentsCell.tsx`,
  `InteractionsTable.tsx`; backend — `backend/students-table/index.py`.
- НЕТ системы сотрудников/ролей: вход = один общий пароль `426874`
  (sessionStorage `admin_authenticated` / `admin_password`), роли на
  `RoleSelectPage.tsx` — только навигация, права нигде не проверяются, маршруты
  `/admin/*` не защищены. «Автор» записи выбирается вручную из хардкод-списка ADMINS.
- НЕТ телефона ученика: `phone` не читается из CRM customer и не отдаётся в items.
  В AlfaCRM телефон скорее всего есть — нужно начать подтягивать.

**План (по этапам):**
0. Этап 0 (СТАРТ, делаем первым): личные кабинеты сотрудников. Таблица `staff`
   в БД (id, ФИО, телефон=логин, пароль-хэш, роль, статус active/pending, timestamps).
   Самостоятельная регистрация по телефону → статус pending. Логин по телефону+паролю,
   выдаёт сессию. Руководитель в разделе «Сотрудники» подтверждает/меняет роль/
   блокирует. Личный кабинет: своё имя, роль, смена пароля. Защита `/admin/*` только
   после входа + по роли. Старый общий пароль 426874 отключаем (руководителя завести
   первым, вручную/сидом). Бэкенд-функция auth (регистрация/логин/сессии), пароли —
   хэш (bcrypt/pbkdf2), НЕ хранить открытыми.
1. Этап 1 (фундамент): сотрудники + личный вход + роли, защита `/admin/*`,
   авто-подпись автора, «Ответственный» у ученика + передача коллеге + внутренние
   заметки + фильтр «Мои ученики». При включении личных входов старый общий пароль
   перестанет работать — сотрудников завести заранее.
2. Этап 2: единая лента «Коммуникация» у ученика, подтянуть телефон из AlfaCRM,
   привязка сообщений по номеру.
3. Этап 3: Max (Wappi) → в ленту.
4. Этап 4: Telegram → в ленту.
5. Этап 5: звонки + расшифровка (когда будет IP-телефония с записью).

**Что нужно от заказчика для старта этапа 1:** список сотрудников (имя + роль).
